# Arclivo Labs AI Email Automation Backend

The TypeScript files in `src/` are the source of truth. `npm run build` removes stale output and regenerates the production entry point at `dist/server.js`. Never implement a production change only in `dist/`.

## Runtime setup

1. Install Node.js 20 or later.
2. Run `npm install`.
3. Run `npm run setup:owner-auth` in an interactive terminal. It creates `.env`
   when needed, prompts without echoing the password, stores only its salted scrypt
   hash, and generates the required server keys. Running it again securely resets the
   password and invalidates existing sessions without replacing the data encryption key.
4. Configure any remaining values in `.env`.
5. Run `npm run build` and then `npm start`.

Production startup fails closed when owner authentication or data encryption is missing. Deploy behind HTTPS and set `NODE_ENV=production`. If TLS terminates at a reverse proxy, forward `X-Forwarded-Proto: https`.

## Environment variables

- `NODE_ENV`: use `production` in production.
- `PORT`: HTTP listener port; default `5000`.
- `OWNER_PASSWORD_HASH`: scrypt hash generated by the included script.
- `SESSION_SIGNING_KEY`: server-only HMAC key for temporary owner sessions. Never embed it in the mobile app.
- `SESSION_TTL_SECONDS`: owner session lifetime; default 12 hours.
- `DATA_ENCRYPTION_KEY`: base64-encoded 32-byte AES key. Back it up separately; losing it makes stored OAuth and AI secrets unrecoverable.
- `CORS_ORIGINS`: comma-separated trusted browser origins. Native Android calls normally have no browser Origin.
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`: Google OAuth Web application configuration.
- `REQUEST_BODY_LIMIT`: Express JSON limit; default `2mb`. CSV content is additionally limited to 1 MB.
- `SCHEDULER_POLL_MS`: scheduler interval; default 15 seconds.
- `GMAIL_TIMEOUT_MS`: Google request timeout; default 20 seconds.
- `ARCLIVO_DATA_DIR`: test/operations override for the data directory. Do not point tests at production data.

## Authentication and Gmail

The mobile app exchanges the owner password for a short-lived signed session token through `POST /api/auth/session`. The password and permanent server keys are not bundled in the APK. All sensitive endpoints require the bearer session.

Gmail authorization uses the existing scopes, OAuth `state`, and PKCE. Access and refresh tokens are encrypted at rest. Disconnect attempts Google revocation before clearing local credentials.

The callback remains a backend URL. Configure the exact public HTTPS callback in Google Cloud. The Android app opens the authorization URL in the system browser and the backend callback shows completion status.

## Persistence and scheduler limitations

The active persistence implementation is JSON. MongoDB is not implemented and no database migration was performed.

Writes use a serialized in-process mutation queue, temporary file, file flush, atomic rename, and a one-generation backup. The schema is versioned and older records are migrated additively. Suppressions, delivery history, and audit history survive lead deletion.

This JSON implementation supports exactly one backend process and one writable data volume. Do not run multiple replicas or processes against the same file. A future multi-instance deployment requires a transactional database implementation with unique idempotency indexes.

Scheduler behavior:

- Automatic sending defaults to disabled and the default limit remains five per day.
- Only permissioned, unsuppressed, explicitly approved drafts can send.
- Claims are persisted before delivery, with stable queue and message IDs.
- Temporary Gmail failures use bounded exponential backoff with at most five attempts.
- Missing delivery confirmation becomes `delivery_unconfirmed` and is never retried automatically.
- With the existing `gmail.send` scope, Gmail cannot be searched to reconcile uncertain delivery. Reconcile only after checking the Gmail Sent folder, using the protected reconciliation endpoint.
- Day boundaries use the configured IANA timezone, default `Asia/Kolkata`.

## Tests and deployment

Run:

```text
npm run typecheck
npm test
```

Tests create isolated temporary JSON stores and install a mock Gmail transport. They never contact Gmail or send real email.

Deploy the complete generated `dist/` tree, `package.json`, `package-lock.json`, and production dependencies. Back up `data/db.json`, `data/db.json.bak`, and `DATA_ENCRYPTION_KEY` before an upgrade. Run a health check against `/healthz` after starting.
